# 人間による判断記録（Judgments）

本ファイルは、AI同士のエスカレーションや「利便性 vs ガバナンス」の葛藤において、人間（管理者）が下した判断の履歴（判例）を記録するものです。今後のAIによる実装や判断は、この判例を優先して行われます。

## 2026-05-07: PR検閲における開発者体験（DX）とガバナンスの両立方針

*   **課題**: 開発中の「とりあえず動かして試したい」フェーズにおいて、AIの厳格な検閲（FAILによるブロック）が開発者の作業リズム（DX）を阻害する懸念がある。
*   **選択肢**:
    1.  Draft PRを聖域化し、レビューはするがブロックしない（推奨）。
    2.  `[skip ai]` などの特定コマンドによる検閲の完全バイパスを許可する。
    3.  特定のブランチ（Dev環境など）では常にブロックしない設定にする。
*   **判断（判決）**: **選択肢 1（Draft PR 聖域化アプローチ）を採用する。**
*   **理由（IPO監査・セキュリティ観点）**:
    *   Draft PRは `main` へのマージができない仕様であるため、本番環境への物理隔離が担保されている。
    *   `[skip ai]` のような抜け道（バックドア）を作ることは、IPO監査において「誰がどういう権限でバイパスを承認したのか」を証明できなくなるため、憲法の「職務分掌」や「証跡の確保」に反し却下。
*   **実装への反映**:
    *   Cloud BuildのAI検閲ロジック（`pr_reviewer.py`）において、PRがDraft状態の場合は判定がFAILでもStatus Checkを通過させる。Ready for Reviewになった時点で厳格にブロックする。
